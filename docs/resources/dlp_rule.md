# googleworkspace_dlp_rule (Resource)

Manages a Data Loss Prevention (DLP) rule through the Cloud Identity Policy API. A rule can use a simple organizational-unit or Workspace-group scope, or preserve an advanced `policyQuery` CEL expression for existing policies with multi-group targeting. The provider sends `setting_value` as the DLP setting's `setting.value` JSON object, allowing the API's evolving rule schema to be used without guessing undocumented fields.

The API's create, update, and delete operations are asynchronous; Terraform waits for each operation to finish. This resource requires a Google Workspace super administrator and the OAuth scope `https://www.googleapis.com/auth/cloud-identity.policies`. Enable the Cloud Identity API in the associated Google Cloud project. If you set `oauth_scopes` explicitly on the provider, include this scope; for domain-wide delegation, authorize it for the service account.

## Example Usage

```terraform
data "googleworkspace_group" "dlp_alerts" {
  email = "security@example.com"
}

data "googleworkspace_group_members" "dlp_alerts" {
  group_id = data.googleworkspace_group.dlp_alerts.id
}

locals {
  dlp_alert_recipients = [
    for member in data.googleworkspace_group_members.dlp_alerts.members : member.email
    if member.type == "USER"
  ]
}

resource "googleworkspace_dlp_rule" "sensitive_drive_sharing" {
  org_unit_id = "03ph8a2z"

  setting_value = jsonencode({
    displayName = "Sensitive data sharing warning"
    state       = "ACTIVE"
    triggers    = ["google.workspace.drive.file.v1.share"]
    condition = {
      contentCondition = "all_content.matches_dlp_detector('US_SOCIAL_SECURITY_NUMBER', google.privacy.dlp.v2.Likelihood.LIKELY, {minimum_match_count: 1, minimum_unique_match_count: 1})"
    }
    action = {
      driveAction = {
        warnUser = {}
      }
    }
  })
}
```

Google Workspace DLP allows [at most 10 alert recipients per rule](https://knowledge.workspace.google.com/admin/security/view-dlp-content-and-rule-size-limits). The provider rejects longer `action.alertCenterAction.recipients` lists before sending a mutation. Use a group email to notify more users, or explicitly cap a sorted member list with `slice(emails, 0, min(10, length(emails)))` if excluding remaining members is intended.

`dlp_alert_recipients` contains the direct user members of the group; nested groups are not expanded. Insert it into the appropriate notification field in `setting_value` only after creating a comparable rule in the Admin console and reading the exact JSON back with the Policy API or GAM. The alert recipient field shape remains opaque apart from the documented recipient-count limit. The provider omits output-only `policyQuery.sortOrder`, `setting.value.createTime`, and `setting.value.updateTime` from mutation requests without changing the configured scope.

## Import

Import an existing DLP policy using its Policy API resource name:

```shell
terraform import googleworkspace_dlp_rule.sensitive_drive_sharing policies/123456789
```

## Schema

### Required

- Exactly one of `org_unit_id`, `group_id`, or `policy_query` must be set.
- `setting_value` (String) JSON object for the DLP rule's `setting.value`. Supply the exact structure accepted by the Policy API. Alert notifications support at most 10 recipients; use a Google Group email address to notify more users.

### Optional

- `org_unit_id` (String) ID of the organizational unit to which this DLP rule applies. Accepts the raw ID or `orgUnits/{id}`. The scope is immutable.
- `group_id` (String) Google Workspace group ID targeted by this DLP rule. Accepts the raw ID or `groups/{id}`. The scope is immutable.
- `policy_query` (String) JSON object containing an advanced Cloud Identity Policy query scope. Use instead of `org_unit_id` or `group_id` for policies whose `policyQuery` uses a CEL `query` expression. The scope is immutable.
